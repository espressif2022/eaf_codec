# Synthetic benchmark assets

This directory is generated by `bench/generate_synthetic_assets.py`. All pixels
are procedural and deterministic; no customer or third-party source material is
included. The generated PNGs may be redistributed with this repository.

## Coverage

| Scene | Purpose |
| :--- | :--- |
| `flat_ui` | Flat colors, hard edges and small moving UI regions |
| `alpha_glow` | Continuous straight Alpha and non-zero hidden RGB |
| `dark_gradient` | Near-black gradients and low-amplitude changes |
| `fine_lines` | One-pixel lines and high-contrast chroma edges |
| `natural_motion` | Smooth multi-frequency motion similar to clouds or fluid |
| `high_frequency` | Temporal grain, dense texture and BTC raw-escape pressure |
| `pan_scroll` | Full-frame translation, difficult for same-position tile deltas |
| `micro_motion` | Mostly static content with a very small moving region |
| `color_key` | Exact black RGB565 key (`0x0000`) and hard transparency edges |

All scenes contain 24 RGBA8 frames. Most are 160×160; `pan_scroll` is 320×160.
The authoritative dimensions and descriptions are in `manifest.json`.

## Reproduce

```bash
python3 bench/generate_synthetic_assets.py
make host-quick
make host-bench
```

`make host-quick` samples six frames from these scenes and from `assets/visual`, and normally finishes much
faster than the exhaustive matrix. It writes machine-readable acceptance data
to `build/host_quick_report.json` and returns non-zero if lossless roundtrips,
the EAF Bounded `maxErr <= 8` bound, payload generation, or the C decoder fails.

Regeneration replaces only `frame_*.png` files inside the known scene folders.
Increment `GENERATOR_VERSION` when pixel generation changes so benchmark reports
can identify their source precisely.

`manifest.json` records SHA-256 hashes over the generated RGBA pixels, so a run can
identify its exact source dataset without depending on PNG encoder metadata.
`make assets` also regenerates the six-frame
`assets/eaf_samples/synthetic_lossless.eaf4` LVGL fixture from `micro_motion`.
